# AI Data Extraction and Browser Workflow Governance

**Audience:** Researchers, analysts, and operators collecting data from sources they are authorized to access.  
**Language:** English (`en`).  
**Permission rule:** browser capability never creates collection authority.

## Select the smallest acquisition route

| Source shape | Recommended starting route | Why | Escalate only when |
|---|---|---|---|
| Official export/API | Consume the documented response; use Scrapy for repeated authorized HTTP traversal | No browser or model is needed to expose already structured fields | Pagination/authenticated identity or a changed contract requires a reviewed adapter |
| Static HTML table | Scrapy selectors with frozen HTML; Crawlee for Python when queue/retry/storage orchestration is the missing layer | Deterministic locators are auditable | Required content is actually generated by browser JavaScript |
| JS-rendered page | Playwright capture plus deterministic DOM extraction | Explicit contexts and network/event observations support controlled capture | DOM text does not expose the required visual field |
| Existing WebDriver/grid organization | Selenium with pinned browser/driver and explicit waits | Reuse the supported grid ecosystem rather than switching solely for fashion | The maintained grid cannot reproduce the target interaction |
| Markdown-oriented web pipeline | Crawl4AI or Firecrawl as a normalization layer | Their declared extraction surfaces fit model-ready representations | Raw capture/field evidence is lost or hosted/local routes differ |
| PDF/office attachment | Docling for layout-aware parsing; MarkItDown for working text; Unstructured for element partitioning | Select the representation the required field needs | A parser lacks the field or fails a frozen fixture |
| Screenshot-only visual state | OmniParser proposes visual elements; a human/source comparison checks them | Screen coordinates are candidate interpretation, not source truth | The question requires actions beyond the read-only envelope |
| Variable navigation genuinely requiring a model | browser-use in a bounded capture lane | Reserve agent reasoning for uncertain navigation, not straightforward tables | Never escalate to bypass access or data-source limits |

n8n coordinates approved capture/validation/review/export steps; it is not an extraction engine. A route need not install all twelve projects. Source evidence supports each component's declared role, not direct interoperability between adjacent tools.

## Three worked route decisions

**Static price table:** freeze HTML and use deterministic row/header locators. The [field-lineage fixture](assets/field-lineage-example.json) finds Basic at 12 EUR/month, but a second synthetic PDF says 15 EUR/month. Preserve both raw values and hold the normalized price instead of choosing whichever looks current.

**JS availability:** use Playwright to capture rendered DOM and network status; keep availability UNKNOWN if the request fails. A model must not turn missing evidence into false, zero, or an empty string.

**PDF product limit:** use Docling when page/box layout is needed; use MarkItDown only if working-text conversion retains the relevant field. Compare parser output to a frozen source region before promotion. Unstructured is an alternative when typed elements and attachment partitioning are the better input contract.

## Acquisition state machine

```text
PROPOSED → AUTHORIZED → CAPTURED → DERIVED → VALIDATED → RETAINED
     |          |           |          |           |
   reject     stop        quarantine  reject     correct
```

The [acquisition policy and field lineage contract](assets/acquisition-policy.json) owns every transition. A state cannot advance because a page returned HTTP 200 or an AI agent found a way around a control.

## PROPOSED — define the dataset and decision

Write the exact fields, population, time period, source owner, intended decision, null policy, duplicate identity, and update cadence. If no decision changes, do not collect the field. Minimize personal and sensitive data at design time.

## AUTHORIZED — establish route and limits

Record permitted base URLs and paths, account and profile, geographic or contractual route, allowed methods, robots/terms review, personal-data basis, requests per minute, concurrency, retention, and owner. Stop at CAPTCHA, access denial, unexpected login, scope redirect, or explicit throttling. This guide does not bypass any of them.

## CAPTURED — freeze what the source returned

Prefer an official API or export, then structured markup, then deterministic DOM selection, then a rendered browser. Use AI vision only when deterministic representations cannot answer the authorized question. Preserve URL, method, timestamp, time zone, status, headers as allowed, body/file/screenshot hash, browser/tool version, network log, and error. Failure stays unknown.

## DERIVED — keep field lineage

For each field, record source snapshot ID, selector/page/region, extraction method, parser or model version, prompt/config hash, raw value, normalized value, confidence, and conflicts. A Markdown conversion or model-ready chunk is not the source document. Never discard the representation needed to audit the field.

## VALIDATED — run two different tests

A frozen fixture tests reproducibility: the same code and configuration should produce the expected schema and values. A current-source test detects site and schema drift. Do not “fix” a changed selector by accepting whatever nearby text the model chooses. Validate types, ranges, enums, cross-field invariants, duplicates, and a sampled visual/source comparison.

## RETAINED — publish data, not hidden custody

Define which raw captures and derivatives remain, for how long, under which access policy, and how corrections or deletion propagate. Public release requires an independent rights/privacy review and a separately authorized exact dataset hash.

## Browser authority envelope

Use a disposable context unless a named account requires a governed profile. Allowlist domains, methods, downloads, and external applications. Quarantine files. Deny clipboard, local files, arbitrary process launch, and credential export by default. Require a human for form submission, message send, purchase, destructive action, or consent acceptance.

## Layer catalogue

### Acquisition runtimes

**[Playwright](https://github.com/microsoft/playwright)**  
Role: browser automation. Drive reviewed browser interactions with isolated contexts and observable network/events.  
Control: Automation authority is the user authority; restrict domains, downloads, methods, profiles, and secrets, and avoid brittle hidden waits.  
License: Apache-2.0.

**[Selenium](https://github.com/SeleniumHQ/selenium)**  
Role: WebDriver automation. Automate browsers through the WebDriver ecosystem.  
Control: Driver/browser versions, waits, downloads, and remote-grid credentials must be pinned and audited; execution is not permission.  
License: Apache-2.0.

**[Crawlee for Python](https://github.com/apify/crawlee-python)**  
Role: crawler runtime. Manage request queues, browser or HTTP crawling, retries, and storage.  
Control: Respect authorization and source limits; retries and concurrency can amplify load or duplicate effects.  
License: Apache-2.0.

**[Scrapy](https://github.com/scrapy/scrapy)**  
Role: HTTP crawler framework. Build deterministic request, parsing, scheduling, and export pipelines.  
Control: Middleware and retry settings can change identity and rate; capture configuration and never infer access rights from technical reachability.  
License: BSD-3-Clause.

**[Crawl4AI](https://github.com/unclecode/crawl4ai)**  
Role: AI-oriented web extraction. Produce model-ready web representations and structured extraction.  
Control: LLM-friendly text can omit layout or controls; preserve raw capture, selectors, versions, and field-level evidence.  
License: Apache-2.0.

**[Firecrawl](https://github.com/firecrawl/firecrawl)**  
Role: web acquisition and extraction. Crawl or scrape pages into normalized representations through a self-hostable stack.  
Control: Cloud and self-host paths may differ; inspect egress, queues, browser services, license, rate limits, and retained content.  
License: AGPL-3.0 core; verify hosted-service terms.

**[browser-use](https://github.com/browser-use/browser-use)**  
Role: LLM browser agent framework. Let a model propose browser actions in a controlled environment.  
Control: Model actions are nondeterministic and prompt-injectable; enforce allowlists, read-only defaults, step budgets, and human effect approval.  
License: MIT.

### AI/visual interpretation

**[OmniParser](https://github.com/microsoft/OmniParser)**  
Role: screen parsing research. Derive candidate interface elements from screenshots for UI understanding.  
Control: Visual detections and coordinates can be wrong or stale; never use them alone for destructive or credential-bearing actions.  
License: the repository LICENSE is CC-BY-4.0 while its current README shows an MIT badge and version-specific model terms. Treat this as an unresolved component/version distinction; do not issue one universal license badge.

### Document derivation

**[MarkItDown](https://github.com/microsoft/markitdown)**  
Role: document normalization. Convert downloaded office/document inputs to reviewable text.  
Control: Treat downloads as untrusted, preserve source hashes, and record format-specific loss before trusting extracted fields.  
License: MIT.

**[Docling](https://github.com/docling-project/docling)**  
Role: layout-aware document parsing. Extract structured content from PDF and document layouts.  
Control: Tables, reading order, formulas, and scans require fixture-based validation; parser output is derivative evidence.  
License: MIT.

**[Unstructured](https://github.com/Unstructured-IO/unstructured)**  
Role: document partitioning. Partition files and messages into typed elements for extraction pipelines.  
Control: Strategy and connector choice alter outputs and data egress; pin configuration and validate element lineage.  
License: Apache-2.0.

### Workflow coordination

**[n8n](https://github.com/n8n-io/n8n)**  
Role: workflow orchestrator. Coordinate acquisition, validation, review, and approved export steps.  
Control: Its sustainable-use license is not a standard OSI license; credentials, community nodes, retries, and effectful nodes need governance.  
License: Sustainable Use License / enterprise terms; verify current license.

## Field-lineage example

| Field | Snapshot | Locator | Method | Value state | Reviewer |
|---|---|---|---|---|---|
| `published_at` | `S-001` | JSON-LD path | deterministic parser | observed | pending |
| `price` | `S-001` | table row + header | DOM selector | conflict | pending |
| `product_limit` | `S-002` | PDF page and box | layout parser | observed | pending |
| `availability` | none | none | none | unknown | pending |

“Unknown” is a valid state. It is better than a zero, false, or empty string manufactured by network failure.

## Drift response

When current extraction differs from a frozen fixture, stop promotion, preserve both captures, classify transport versus layout versus semantics, update source locators, rerun the sample review, and version the schema. Never rewrite historical source evidence to match a new page.

## Evidence discipline

The canonical source register is [`sources.json`](sources.json). Run `python3 scripts/verify.py` to check exact source/evidence binding, acceptance hashes, synthetic fixture invariants, English narrative, and the presence of the [acquisition policy and field lineage contract](assets/acquisition-policy.json). Reachability is transport evidence only. Re-read release guidance, licenses, model terms, and security notices before adoption.

## Source upkeep and reuse

The source register links exact-revision evidence excerpts. Recheck on upstream deprecation, license changes, representation changes or fixture drift; otherwise avoid date-only updates. Original guide and examples: CC BY 4.0; linked projects retain their terms.
